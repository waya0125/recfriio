# SKNET MonsterTV U3S（EM28178 + TC90522 x2 + FC0013 + QM1D1C0042）

SKNET MonsterTV U3S（`SK-MTVU3S`）は、地上デジタル（ISDB-T）・BS・110 度 CS（ISDB-S）の 3 波に対応した USB 2.0 チューナーです。  
Go 版の `recfriio --u3s`（`recmtvu3s` と同じ）で使うときの説明と、中身を調べた結果をまとめます。共通の使い方とオプションは [README](../README.md) にあります。

QRS-UT100B と違って **ファームの転送は不要**（USB につないだ直後から `3275:9015` として認識）です。`--b25` で録画に使う U3S の内蔵 B-CAS スロットを使い、`--pcsc` で外付けへ切り替えます（3 章）。

## Go 版での使い方

C/C++ 版の recfriio の `--u3s`（`Mtvu3s`・`Tc90522`・`Fc0013`・`Qm1d1c0042`）を Go に移したものです。

```bash
bin/recfriio --u3s --stats 21 30 out.ts       # 地デジ
bin/recfriio --stats BS15_0 30 out.ts         # BS（BS・CS は U3S しか受けられないので --u3s は無くてもよい）
bin/recfriio --stats CS2 30 out.ts            # 110 度 CS
bin/recfriio --u3s --b25 BS15_0 30 out.ts    # 内蔵カードでB25復号
bin/recfriio --u3s --pcsc BS15_0 30 out.ts   # 外付けカードリーダーでB25復号
```

### U3S での動き

- USB は isochronous（EP `0x84`、altsetting 1、940 バイト × 16 フレーム / URB）で受けます（`internal/usbfs` の `StartIsoStream`）。
- EM28178 が USB 転送でかける AES-128-ECB は、`internal/mtvu3s` の `Descrambler` で外します。  
  `--no-descramble` を付けると外さずに書き出します（照合用。ペイロードは暗号がかかったまま）。
- 受け始めの、復調部が落ち着く前のパケット（TEI 付き。地デジで 1 秒弱）は捨てます（`Settler`）。  
  TEI の無いパケットが 5,000 個続いたら書き出し始めます。`--no-settle` で捨てずに書き出します。
- 衛星は、TMCC に載っている TSID の一覧と突き合わせて TS を選びます。  
  BS は、登録年のビット（`0x0e00`）を無視して当てます（`BS23_1` → `0x4971` など）。  
  CS は表（CS2 = `0x6020`、CS8 = `0x6080`、CS10 = `0x60a0` など）から渡し、合わなければネットワークのビット（`0x1000`）を無視して当てます。  
  一覧に無い TS（例: 2026-11-19 の `BS23_2`）を頼むとエラーで止まります。  
  C/C++ 版は黙って別の TS（一覧の最初）を出していました。
- `--b25` は内蔵カードを使います。従来どおり外付けの PC/SC リーダーを使う場合は `--pcsc` を指定します。
- `--stats` はヘッダーだけを数えます。ペイロードは見ないので、暗号がかかったままでも使えます。
- 地デジの C/N は Linux の tc90522 と同じ式です（C/C++ 版の U3S の式とは値が違います。2.7）。
- 試験: `internal/mtvu3s/golden_test.go` が、チップの手順で I2C に送るバイト列を、C/C++ 版のクラスで取った記録（`testdata/i2c-golden.txt`、1,601 行）と比べます。

### 確かめた結果

2026-11-19 の実機（`--no-descramble`、暗号を外す前の TS のヘッダーで確かめた結果）:

| チャンネル | 長さ | パケット | 同期の乱れ | TEI | 連続カウンターの飛び | C/N |
|---|---|---|---|---|---|---|
| 地デジ ch21 | 5 秒 | 99,551 | 0 | 0 | 0 | 31.4 dB |
| BS15_0 | 5 秒 | 79,493 | 0 | 0 | 0 | 13.8 dB |
| CS2 | 5 秒 | 173,422 | 0 | 0 | 0 | 10.6 dB |
| 地デジ ch21（頭を捨てない） | 60 秒 | 1,195,083 | 0 | 6,369 | 69 | 31.1 dB |
| 地デジ ch21（頭を捨てる） | 60 秒 | 1,181,834 | 0 | 0 | 0 | — |

頭を捨てないときの TEI は全部、受け始めの 1 秒に固まっていました（ロックの直後で、復調部がまだ落ち着いていない）。  
C/C++ 版の確かめも末尾だけを数えていた（`tail20k_tei`）ので、たぶん同じことが起きています。  
衛星の TS は、PAT の `transport_stream_id`（暗号のかかっていない 8〜9 バイト目）で確かめました（CS2 = `0x6020`、BS15_0 = `0x40f1`、BS01_0 = `0x4010`、BS23_1 = `0x4971`、BS23_3 = `0x4973`）。

`recfriio` 1 つにまとめたあと（2026-11-19）も、UT100B と同時に動かして、使用中の UT100B を避けて U3S が選ばれること、地デジ 21〜26ch・BS15_0・CS4 で同期の乱れ・TEI・連続カウンターの飛びが 0 であることを確かめました。  
AES を外したあとと `--b25` の結果は 5 章にあります。

### バス構成図

```text
USB (EM28178, 3275:9015, High-Speed 480Mbps)
 ├── EP 0x00 (Control): レジスタ R/W (req=0x00), I2C (req=0x02/0x03)
 ├── EP 0x84 (Isochronous, altsetting=1, 940B/pkt): TS ストリーム (AES-128-ECB 暗号化)
 └── I2C バス
      ├── 0x20: TC90522 (ISDB-T) ──[0xfe リピータ]──▶ 0xc6: FC0013 (UHF チューナー)
      └── 0x22: TC90522 (ISDB-S) ──[0xfe リピータ]──▶ 0xc0: QM1D1C0042 (BS/CS チューナー)
```

### USB 転送の仕様

- **Interface**: `0`
- **Altsetting**:
  - `0`: アイドル（ストリーム停止）
  - `1`: ストリーム有効（Isochronous IN `EP 0x84`, `wMaxPacketSize = 940` = 188 × 5 バイト）
- **URB の構成**:
  - C++ 版: `940B × 16 packets/URB`（1 URB = 2ms）、`32 URBs` を予約
  - Go 版: `940B × 16 packets/URB`、`128 URBs` を予約（GC などでの取りこぼしに余裕を持たせる）

## 2. 制御の手順

### 2.1 EM28178 の USB ベンダーリクエスト

| `bmRequestType` | `bRequest` | `wIndex` | 用途 |
|---|---|---|---|
| `0x40` (OUT) / `0xc0` (IN) | `0x00` | レジスタ番号 | EM28178 内部レジスタ 1 バイト R/W |
| `0x40` (OUT) / `0xc0` (IN) | `0x02` | I2C アドレス (8bit) | I2C R/W（**STOP あり**） |
| `0x40` (OUT) / `0xc0` (IN) | `0x03` | I2C アドレス (8bit) | I2C R/W（**STOP なし** / Repeated Start） |

- 復調器のレジスタは、`req=0x03` でレジスタ番号を 1 バイト書いたあと、`req=0x02` の IN で読み出す。
- チューナーのレジスタ（TC90522 の `0xfe` リピータ経由）は、次の 3 段階で読む。
  1. `req=0x02`（OUT）で `[0xfe, tunerAddr, reg]` を送る（STOP あり）
  2. `req=0x03`（OUT）で `[0xfe, tunerAddr | 0x01]` を送る（STOP なし）
  3. `req=0x02`（IN）で 1 バイト読み出す

### 2.2 EM28178 の初期化・GPIO（EEPROM の解析から）

`emBDA64.sys` は EEPROM の `0xb0..0xc1`（機能番号 → GPIO の対応表）を読み、`0x80` ポートの 2 本だけを有効にしている（地上波/衛星の RF スイッチや外部 LNA 用の GPIO は無い）。

- **GPIO1（`0x80` bit1）**: 電源（**Low で ON**、High で OFF）
- **GPIO7（`0x80` bit7）**: リセット線（Low → 待ち → High のパルス）

起動の手順:
1. `reg 0x0c = 0x10`（USB サスペンド解除 / 電源）
2. `reg 0x06 = 0x44`（I2C クロックの設定。Windows のキャプチャでは `0x46` も使う）
3. `reg 0x80 = 0x7c` → 50ms 待ち → `reg 0x80 = 0xfd`, `reg 0x73 = 0xfd`（電源 ON・リセット解除＋シャドウレジスタ）→ 50ms 待ち

### 2.3 USB 転送の暗号（EM28178 の AES-128-ECB）

`emBDA64.sys`（`0x1dee8` / `0x642d4` / `0x4dea4`）の解析で分かったこと:
- **鍵レジスタ**: `reg 0x60..0x6f`（16 バイト）。全部 0（`0x00` × 16）を書き込むと固定の鍵になる。
- **TS の制御レジスタ**:
  - `reg 0x5d = 0xef`（TS インターフェースの制御）
  - `reg 0x5f = 0x89`（TS1 有効化 + Sync + カスタム鍵の暗号化 ON。停止時は `0x08`）
  - `reg 0x50 = 0x01`（ISDB-T を使うとき。Windows のキャプチャで確認）
- **暗号の範囲**: 188 バイトの TS パケットのうち、
  - `pkt[0..11]`（12 バイト）: **平文**（同期バイト `0x47`、TEI、PID、CC などは復号前でも読める）
  - `pkt[12..187]`（176 バイト = **11 ブロック × 16 バイト**）: **AES-128-ECB** で暗号化
- **同期の取り方**: isochronous で受けたデータから、`0x47` が 188 バイト間隔で 3 つ続く位置を探してパケットの区切りを合わせ、外れたら合わせ直す。

### 2.4 TC90522 x2（`0x20` ISDB-T / `0x22` ISDB-S）の初期化と切り替え

2 基の TC90522 が TS の出力バスを共有しているため、**使わない側の TS ピンをトライステート＆スリープにすることが必須**。

- **ISDB-T（`0x20`）の初期化**（`emOEM64.sys` `0x6a3dc` / `0xfbd50` の `flag==1` の行）:
  - `0x0e=0x01`（起動。`0x77` はスリープ）, `0x0f=0x77`
  - `0x01=0x40`, `0x20=0x00`, `0x21=0xff`, `0x22=0x8f`, `0x23=0xfc`, `0x24=0x4c`, `0x25=0x80`, `0xf4=0x80`
  - 初期状態は `0x1d=0xa8`（TS ピンはトライステート）
- **ISDB-S（`0x22`）の初期化**（`emOEM64.sys` `0x6a3dc` / `0xfc350` の `flag==1` の行）:
  - `0x07=0x01`, `0x08=0x10`（クロックの設定）
  - `0x15=0x00`, `0x1d=0x00`, `0x0a=0xff`, `0x10=0xb1`, `0x11=0x40`, `0x85=0x7a`, `0x87=0x04`, `0x03=0x01`
  - 初期状態は `0x1c=0x80, 0x1f=0x22`（TS ピンはトライステート）
  - `0x85=0x7a, 0x87=0x04` が抜けると、`0xc5` が `0x2c` に留まり、全パケットが `TEI=1` になる。
- **バンドの切り替え**:
  - **地デジへ**: `0x22` を `0x1c=0x80, 0x1f=0x22`（トライステート）→ `0x20` を `0x0e=0x01, 0x0f=0x77, 0x1d=0x00, 0x1f=0x00`
  - **BS/CS へ**: `0x20` を `0x0e=0x77`（スリープ）, `0x1d=0xa8`（トライステート）→ `0x22` を `0x1f=0x00, 0x1c=0x05`

### 2.5 地デジの選局（FC0013 + TC90522 `0x20`）

1. **FC0013 の初期化**（`emOEM64.sys` `0x32c78`）:
   - `0x01..0x15` に `{09, 16, 00, 00, 17, 02, 2a, ff, 6f, b8, 82, fe, 01, 00, 00, 00, 00, 00, 00, 50, 01}` を書き込む。
2. **選局の前後の TC90522 の AGC ホールド（いちばんのハマりどころ）**:
   - Windows の `usbmon` キャプチャ（`u3s_win_full.pcap`）で分かった。これをしないと `0x20[0x80]` が `0xae`/`0xaf` のまま、まったくロックしない。
     - **選局前**: `0x20[0x25] = 0x00`, `0x20[0x23] |= 0x01`（`0xfc -> 0xfd`）
     - **FC0013 の選局**
     - **選局後**: `0x20[0x23] &= ~0x01`（`0xfd -> 0xfc`）, `0x20[0x25] = 0x80`, 50ms 待ち → `0x20[0x01] = 0x40`
3. **FC0013 の選局**（`emOEM64.sys` `0x330e8` / `0x338de`、Zero-IF、`xtal = 28800 kHz`、`bw = 6 MHz`）:
   - `0x1d |= 0x1c`, `0x07 &= 0xef`, `0x14 = (r14 & 0x1f) | (freq <= 862000 ? 0x40 : 0x20)`
   - VCO の上限 `3,560,000 kHz` をもとにした 10 段の分周表（`multi = 96, 64, 48, 32, 24, 16, 12, 8, 6, 4`）で `am`/`pm`/`k`（`pm < 11` なら `xtal/2`・`r09=0x6f`）を計算し、`0x01..0x06`, `0x09` に書き込む。
   - `0x11` の bit2 は、`multi == 64` のときだけ 1 にする。
   - VCO のキャリブレーション: `0x0e = 0x80 -> 0x00 -> 0x00`。`(read(0x0e) & 0x3f) > 0x3c` なら `r06 &= 0xf7` にしてやり直す。
   - 選局後に固定で書く値: `0x08 = 0x1f`, `0x0c = 0xf8`, `0x14 = 0x50`。
4. **LNA の調整**（`emOEM64.sys` `0x33c00`）:
   - `0x12=0, 0x13=0` を書いてから `0x12`/`0x13` を読み、総ゲインに応じて `0x14` の LNA の段（`0x00` / `0x08` / `0x10`）を切り替える。ロック待ちのループの中で行う。
5. **受け始めの TEI**（Go 版は `Settler` で対処済み）:
   - 地デジは、ロック直後の約 0.5〜1 秒、復調器が落ち着く前に `TEI=1` のパケットが数千個出る。Go 版は落ち着くまで先頭を捨てて、出力する TS 全体を `tei=0, cc_err=0` にしている。

### 2.6 衛星の選局（QM1D1C0042 + TC90522 `0x22`）

- `QM1D1C0042`（`xtal = 16000 kHz`）で選局したあと、`0x22[0x03] = 0x01` でソフトリセットする。
- `0x22[0xc3] & 0x10 == 0` で TMCC のロックを待ち、`0x22[0xce]`（24 バイト）から TSID の一覧を取って `0x8f`/`0x90` に設定し、`0x03 = 0x01` でもう一度リセットする。
  - 一覧は、ロックの直後にはまだ埋まっておらず、`0xfff8` などの埋め草（`0xfff0` 以上）しか無いことがある。Go 版は埋め草以外が入るまで待つ。
- `0x22[0xc5] & 0x03 != 0` でスロットのロックが完了する。
- 周波数の計算:
  - UHF（`13..62`）: `473143 + (ch - 13) * 6000` kHz
  - BS（`BS01_0..BS23_7`）: `1049480 + ((node - 1) / 2) * 38360` kHz（`BS15` は ARIB の決まりでスロット番号 +1）
  - CS（`CS2..CS24`）: `1613000 + (ch/2 - 1) * 40000` kHz

### 2.7 C/N の計算

- **ISDB-S（`0x22[0xbc..0xbd]`）**: 16bit の `cndat`（`< 3000` は 0 dB）。`p = sqrt(cndat - 3000) / 64.0` に対する 5 次多項式（Linux の `tc90522.c` と同じ）。
- **ISDB-T（`0x20[0x8b..0x8d]`）**: 24bit の `cndat`
  - C++ 版: `10 * log10(2^24 / cndat)`
  - Go 版: Linux の `tc90522.c` / `Hdp.cpp` と同じ式（`10 * log10(5505024 / val)` の 4 次多項式）にそろえた。

## 3. B-CAS

- `--b25` は録画に使う U3S と同じ個体の内蔵カードを使う。初期化に失敗した場合はスクランブルを外さずに録画を続け、終了コードを 1 にする。
- `--pcsc` は外付けの PC/SC カードリーダー（例: `ACS ACR39U`）を使う。`--b25` を併記した場合も外付けを優先する。
- 本番の `mirakurun` コンテナがカードリーダーを使っている環境でも、`PCSCLITE_CSOCK_NAME=/proc/<pid>/root/run/pcscd/pcscd.comm` でソケットを借りて外付けで復号できることを旧版の `--b25` で実機確認済み。現行版では `--pcsc` を使う。

### 内蔵のスロット

Go の内蔵カード処理は、U3S BonDriver の試験用 `winscard.dll` で確認した手順を移植した。録画用のUSB接続で T=1 を扱い、初期設定と ECM の実機確認済み形式の応答を戻す。対応するATRは下記のもの、送信APDUは最大124バイト（ECM本体は118バイト）。合成応答を使うテストで検証済み。内蔵カードを使いながらのLinux実機の録画は未検証。

録画中の ECM 失敗時の再接続は1回まで。通信に失敗した時点までの出力は書き出すが、その間は一部のパケットにスクランブルが残ることがある。APDUが上限を超える場合はエラーを表示して録画を終了する。その放送を録画するには `--pcsc` で外付けを使うか、B25復号を無効にする。

#### 2026-11-19 の調べ

ハードウェアとしてはカードスロットがある（付属 CD のユーザーズガイドの仕様の欄、同梱品に B-CAS カード）。  
USB の CCID のリーダーではなく、EM28178 の中のカードのコントローラー（ISO 7816、T=1）を、ベンダーの要求 `0x14` とレジスタ `0x70..0x75` で使う作り（`emBDA64.sys` `0x3f80c` の解析と実機で確かめた）。

| 段 | 手順 |
|---|---|
| 電源・ATR | `reg 0x73 = 0x00` → 700ms 待つ（EM28178 の中でカードのリセットと ATR の受け取りまで進む）→ `0x70 = 0x05`、`0x71 = 13` になり、要求 `0x14`（IN、`wIndex 0x0000`）で ATR を読める |
| 送る | 要求 `0x14`（OUT、`wIndex 0x0200` + 位置）で T=1 のブロックを書く → `0x75 = (0x75 & 0xfb) \| 0x01` → `0x70 = 0xff` → `0x71` = 送るバイト数 |
| 待つ | `0x70 & 0x05 == 0x05` になるまで読む。送り始めた直後は前の答えの状態が長さ 0 のまま見え、答えの途中でも立つので、頭の 3 バイトの LEN で全部そろうまで待つ |
| 受ける | `0x71`（下位）・`0x72`（上位）で長さを読み、要求 `0x14`（IN、`wIndex 0x0000` + 位置）で読む |

要求 `0x14` は 1 回に 64 バイトまで（それより長く読むと `EOVERFLOW`）なので、`wIndex` を 64 バイトずつずらして分ける。

実機で確かめたこと:
- ATR（`3bf01200ff9181b17c451f0399`）と、S(IFS) の答え（`00e101fe1e`）は、そのまま正しく読める。
- B-CAS の初期設定（INT、`90 30 00 00 00`）の答えは、長さ（65 バイト）・初期設定の番号（`0x2100`）・SW（`90 00`）は合うが、その先の中身が違う。
  - LRC が合わない（読み直しても、64 バイトの切れ目をずらしても同じ値。IFSD を 32 にして分けて受けても、どのブロックも合わない）。
  - CA_system_id が `0x0005` ではなく `0xcc57` になる。
  - カードによらないはずのシステム鍵と CBC の初期値が、UT100B の内蔵スロットのカードのものと違う（ハッシュで比べた）。
- 挿していたのは星の数が違う赤 B-CAS カードだが、カードの世代で LRC や CA_system_id が変わることはない。そのため、カードの答えは EM28178 の中で保護・変換されていると判断した。

当時は保護を外さない方針で、上の手順で送り受けする Go のコードは repo の外（作業メモ）に置いていた。
